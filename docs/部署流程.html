Cube Console + Cube Compose 部署流程

标准目录：/opt/cube-console；根目录 Compose：compose.yml；配置：.env；状态：state/。

一、项目结构

cube-console/
├── compose.yml                 # 主编排文件
├── .env.example                # 环境变量模板（提交 Git）
├── .env                        # 目标环境密钥（不提交）
├── Dockerfile                  # 配置台镜像
├── services/gateway/           # 内置 Nginx Gateway
├── server/ public/             # 配置台源码
├── state/                      # 模型、术语、数据源等运行状态（不提交）
└── docs/
统一约定：线上和内网都使用项目名 cube-console 与目录 /opt/cube-console。旧目录只保留归档，不作为运行入口。

二、首次部署

install -d -m 755 /opt/cube-console
git clone --branch <发布Tag> <GIT_URL> /opt/cube-console
cd /opt/cube-console
cp .env.example .env
chmod 600 .env
mkdir -p state/{schema,modules,glossary,openapi}
docker compose --env-file .env config --quiet
docker compose --env-file .env up -d --build

离线环境先导入镜像，再使用 docker compose --env-file .env up -d --no-build。

三、必须填写的 .env

STACK_NAME=cube-console
GATEWAY_CUBE_PORT=18080
GATEWAY_CONSOLE_PORT=18081
CUBE_PUBLIC_BASE=http://内网IP:18080
CONSOLE_PUBLIC_BASE=http://内网IP:18081
CUBE_IMAGE=cubejs/cube:v1.7.25
CONSOLE_IMAGE=cube-console:unified
GATEWAY_IMAGE=cube-console-gateway:1.0.0
CUBE_UI_ADMIN_TOKEN=随机管理令牌
CUBEJS_API_SECRET=随机长密钥
CUBEJS_DB_TYPE=mysql
CUBEJS_DB_HOST=目标数据库地址
CUBEJS_DB_PORT=3306
CUBEJS_DB_NAME=目标数据库
CUBEJS_DB_USER=目标用户
CUBEJS_DB_PASS=目标密码
容器内部通过 cube_api:4000 连接 Cube；数据库地址填写目标环境可达的内网 IP、服务名或 host.docker.internal，不要默认填写 127.0.0.1。

四、验证

docker compose --env-file .env ps
curl http://部署机IP:18080/gateway-healthz
curl http://部署机IP:18080/readyz
curl http://部署机IP:18080/openapi.yaml
curl http://部署机IP:18081/healthz
  • 配置台：http://部署机IP:18081
  • Cube/OpenAPI：http://部署机IP:18080
  • 首次进入后，在“数据源”中配置目标数据库，再导入业务术语和语义模型。

五、升级与回滚

备份：tar -czf /opt/archives/cube-console-state-时间.tar.gz state
升级：git fetch --tags && git checkout <新Tag> && docker compose --env-file .env up -d --build
回滚：git checkout <旧Tag> && docker compose --env-file .env up -d --build

不要提交 .env、数据库密码、JWT 密钥或 state/。Gitea 作为版本入口，部署机使用只读 Deploy Key。
